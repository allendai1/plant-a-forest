# M1. Hex grid and tiles

Status: **done 2026-10-06.** Rewritten the same day for the giant-sequoia redesign (`docs/DESIGN_CHANGES.md`) and approved with a flat floor.

## 1. Goal

From `docs/MVP_PLAN.md`: ForestService builds the grid with `HexGrid.rings(HubRings + ForestRings)` around a `ForestCenter` part, skipping rings 0–3 (the hub); skips hexes inside `NoPlant` parts; raycasts each plot onto the ground; keeps per-hex server state; counts plantable hexes and sets the tier 1 Forest Bar target = plantable × 35. A minimal client ForestController draws a hex tile per plot, locked or open.

Done when: on a flat test map, 684 tiles appear (ring 15 open, rings 4–14 locked) and the target (23,940) is printed.

## 2. Design check

- **Grid:** "a grid of large hexagonal plots, one giant sequoia per plot" (GDD, forest layout). `HexGrid.rings(15)`, keeping rings 4 to 15 (`HubRings = 3`, `ForestRings = 12`), `HexSize = 16`. Plots are numbered in that ring order; the number is the plot's index in the snapshot and batches (ARCHITECTURE section 6).
- **No-plant volumes:** the MVP map has no paths or stream ("the forest has no paths or other no-plant zones"), but the center-only `NoPlant` check stays because it's a few lines and the map may get decorations inside the forest later. Decided earlier: a hex is skipped only when its center is on a `NoPlant` footprint.
- **Ground:** the server raycasts down at each hex center and stores the hit height. Ground is anything except `NoPlant` parts and characters. Hexes with no ground under them, or landing on terrain water, are skipped (decided earlier).
- **Per-hex state:** index, q, r, ring, position, seeds, species, mutation, starter UserId, tree seed. All start empty (0).
- **Rings, outside-in:** "The forest fills in rings, starting with the outermost ring. The next ring inward opens only when every tree in the current ring is full grown." M1 stores per-ring plantable and finished counts and sets `UnlockedRing = 15`. The unlock logic itself comes in M4.
- **Forest Bar target:** "fixed per tier: every plot times the tier's seeds per hex", via `GameConfig.forestTarget(plantable, Tiers[1].SeedsPerHex)` = 684 × 35 = 23,940. It never depends on player count.
- **Visible tiles:** "every plot is a visible hex tile on the forest floor, about 32 studs across ... locked tiles are dark; open, empty tiles are bright with a glowing rim." M1 draws those two states. The pulse and the started and finished looks come in M5 with trees.

### How a hex works

- **Shape and size:** pointy-top hexes, `HexSize = 16` studs from center to corner, so neighboring centers are about 27.7 studs apart and each tile is about 32 studs across.
- **Coordinates:** axial `(q, r)`; `(0, 0)` is the `ForestCenter` part. World position = `HexGrid.toWorld(q, r, 16, center)` with Y replaced by the raycast ground height. Ring = hex distance from `(0, 0)`.
- **Building the grid:** walk `HexGrid.rings(15)`, skip rings 0 to 3, skip `NoPlant` centers, raycast the rest, and skip any with no ground or on water. What's left is the plot list, numbered 1..N, fixed for every tier.
- **Server storage:** an array of plot records indexed by plot number, plus a `HexGrid.key(q, r) → index` map, so a `PlantSeeds(q, r)` request (M4) is one lookup.
- **Client storage:** the same arrays, mirrored from the snapshot.
- **What players see:** one tile per plot. Trees go on top from M5, offset slightly from the tile's center at random so the forest looks natural.

## What changed from the plan

- **New `Center` attribute on `ForestState`** (a Vector3). Clients need the grid origin to place tiles, and with StreamingEnabled the `ForestCenter` part might not be streamed in on the client. ARCHITECTURE section 6 is updated to match.
- **The `q,r` lookup map and per-ring finished counts were left for M4**, the first milestone that reads them, so M1 doesn't carry unused state. Per-ring plantable counts are stored and printed.
- **The hub clearing disc is 80 studs in radius, not 97.** At 97 it reached under 6 ring-4 tiles, and the ground raycast landed on it 0.2 studs higher than the floor. At 80 every plot sits on the floor.
- **`tools/studio_sync.py` assigns `Source` through a local.** A line starting with `(` right after a call is ambiguous in Luau.
- **Camera settings** on StarterPlayer are back to Roblox's defaults (Zoom, 128). The code sets Invisicam and the zoom cap in M2. The brighter lighting and the moved spawn were kept.

- Missing center: with the tag removed, the server stops with `ForestService: expected exactly one part tagged "ForestCenter", found 0`. Restored afterwards.
