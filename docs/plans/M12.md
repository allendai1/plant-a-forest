# M12: performance pass (and soft-launch prep)

Status: **in progress (2026-10-07).** Started without a plan at the user's request ("just implement"), as part of the soft-launch readiness work.

## Goal

A full forest runs smoothly on phones, measured rather than guessed, before a soft launch.

## Done so far

- **Tile collision removed.** Every tile piece is now CanCollide, CanQuery and CanTouch false (`ForestController` `place()`).
  - **Before:** each of the 540 tiles had a colliding slab, border, tufts and flowers: 2,150 colliding MeshParts per client.
  - **Why it's safe:** players walk on `Map.WalkFloor` (top 1.55), which is above the slab (1.20) and border (1.35). The grass tufts (top 2.64) and flowers (2.0) stuck up through it as bumps.
  - **Verified:** 0 colliding tile parts. A 141-stud walk across tiles held the feet at exactly 1.55, with no jumps.
- **Stray script removed.** The "TreadmillSpawn by Jose" free model (an enabled server script and a LocalScript, waiting forever for a remote that doesn't exist) was deleted. It was read first: no backdoor.
- **Measured without rendering**, because Studio wasn't drawing frames:

  | What, with the forest 99% full | Count |
  | --- | --- |
  | Workspace instances | about 4,900 |
  | MeshParts | 3,523 |
  | Other parts | 94 |
  | Enabled particle emitters | 38 |
  | Lights | 16 |
  | Beams | 19 |
  | Billboards | 21 |
  | Server heartbeat | 60/s |
  | Server network send while idle | 0.5 KB/s |

  Studio's memory numbers (2.6 GB) are the whole Studio process and say nothing about a phone.

## Still to do (needs Studio rendering: bring the window to the front)

1. **Frame rate:** fps with a full forest and the break, at automatic quality and at Level 21. Use the phone emulator (Device: a mid-range phone) and the MicroProfiler. The last numbers (M11) were 15 fps at maximum quality, and 60 at automatic from the spawn and 28 from above.
2. **Special trees:** a forest with many special trees. Each Cherry Blossom, Bamboo or Crystal Tree from stage 4 emits 2–6 particles a second, which lasts 4–6 s for petals. If that's costly, emit only on full-grown trees or lower the rates.
3. **The worst offenders:** fix what the measurements show. The likely ones are tree MeshParts' shadows (CastShadow on 3,500 parts), the far forest (StreamingEnabled doesn't apply to client-built trees: chunk them by distance), and the tier pad effects.
4. **Fast movement:** check streaming keeps up at 200+ walk speed.
5. **Client memory:** in a real client (Developer Console, Memory), not Studio.
