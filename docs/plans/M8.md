# M8. Saving

Status: **done 2026-10-06.**

## 1. Goal

From `docs/MVP_PLAN.md`: a saved player profile (Strength, Speed, coins, upgrade levels, forests completed, tutorial progress) with a schema version, session locking, autosave every few minutes, and a save when you leave and when the server shuts down.

Done when: stats survive rejoining and a forced shutdown, and two servers can't both write the same profile.

## 2. What the player gets

Everything you earn stays with you between visits: Strength, Speed, coins, the three upgrade levels and forests completed (which keep the training stations you've unlocked open).

What isn't saved, on purpose:
- **Carried seeds:** you start each visit empty-handed (decided earlier).
- **The forest:** it belongs to the server, not to a player.
- **Anything about the moment:** benching, running, standing in the spring.

## 3. How (ProfileStore)

ARCHITECTURE already picked **ProfileStore**, loleris's open-source module that most Roblox games use for this. It handles the hard parts:
- **Session lock:** only one server at a time can own your profile. If you join a second server, the first one hands it over and stops writing.
- **Saving:** it autosaves every few minutes, saves when you leave, and saves when the server shuts down (`BindToClose`).
- **New fields:** fields added to the profile later (tutorial, quests) fill in with their defaults automatically.

The rest of the game doesn't change: everything already goes through `DataService.get / set / add`, and the attributes stay as they are.

| File | Change |
| --- | --- |
| `src/server/Vendor/ProfileStore.luau` | **New:** the ProfileStore module, downloaded unchanged from loleris's official GitHub repository (MadStudioRoblox/ProfileStore, Apache-2.0 license, kept beside it as `ProfileStore.LICENSE.txt`). It's excluded from our lint and type checks, since it isn't our code. |
| `src/server/Services/DataService.luau` | **Rewritten inside, same API:** loads each player's profile with ProfileStore when they join, mirrors it to the attributes, and ends the session when they leave. If the session is taken by another server, the player is kicked with a message. If the profile can't be loaded at all, the player is kicked with "Couldn't load your data, please rejoin" (question 3), never given an empty profile that could overwrite their save. |
| `src/server/Services/DevService.luau` | **Adds** `resetProfile`: back to a brand-new player's values, for tests. |
| Lint config | `selene.toml` and StyLua skip `src/server/Vendor`. |
| `docs/ARCHITECTURE.md` | The profile's saved shape (below) and the Vendor folder. |

## 4. Saved data

One DataStore key per player, `Player_<UserId>`, in the store `PlayerData` (question 1 covers Studio):

```lua
{
	Version = 1, -- bumped when a field is renamed or reshaped; DataService migrates old saves on load
	Strength = 0,
	Speed = 0,
	Coins = 0,
	BulkPickupLevel = 0,
	BulkPlantLevel = 0,
	PlantingRangeLevel = 0,
	ForestsCompleted = 0,
}
```

**Change from ARCHITECTURE:**
- **Flat upgrade levels:** saved as flat fields (as DataService and the attributes already name them), not a nested `Upgrades` table.
- **Fields added later:** the tutorial, quest and lifetime fields (`Tutorial`, `QuestsDone`, `SeedsPlanted`, `TreesHelped`, `PlantedInWeather`) are added in M10, when something uses them. ProfileStore fills in their defaults for players who already have a save.

**No new remotes.**

## 5. Decisions

1. Studio saves go to their own store, `PlayerData_Studio`; the live game uses `PlayerData`.
2. The place is published and Studio API access is on (ProfileStore reports "data will be saved").
3. If a profile can't be loaded, the player is kicked with "Couldn't load your data. Please rejoin."
4. ProfileStore was downloaded from the official repository (last updated 31 July 2025).

## 6. Test plan

1. **Static checks** (StyLua, Selene, luau-lsp) and the byte-for-byte sync check.
2. **Rejoin (Done when, part 1):** in Play, set Strength, Speed, coins, the three upgrade levels and forests completed to recognisable values, stop Play, start it again. Every value is back, and carried seeds are 0.
3. **Forced shutdown (Done when, part 2):** change values and stop Play immediately, so the save happens during shutdown rather than on a normal leave. The new values are there next time.
4. **Two servers (Done when, part 3):** while Play holds my profile, start a second session on the same profile from Studio's Edit side (a separate server as far as DataStores are concerned). The play server loses the session and kicks the player with the message; the second session sees the latest values. Writes from the first server after that don't reach the save.
5. **New player:** `resetProfile`, rejoin: everything starts at 0 (with 1 seed capacity, the 1x stations only).
6. **Autosave:** check in the output that ProfileStore saved during a session longer than its autosave interval.

## What changed from the plan

- **ProfileStore's license is Apache-2.0**, not MIT as the plan said. The license file sits beside it.
- **Autosave is ProfileStore's own:** every 300 s (5 minutes), not the 180 s ARCHITECTURE suggested. `Data.AutosaveSeconds` was never added to GameConfig.
- **The two-server test ran the other way round:** Studio's Edit side can't be reached while Play runs, so the Edit side opened the profile first and Play had to take it over.
- **Lint:** Selene (`selene.toml` `exclude`), StyLua (`.styluaignore`) and luau-lsp (`--ignore "src/server/Vendor/**"`) skip `src/server/Vendor`.

**Verified in Studio (one player, through the Studio connection):**
- **Rejoin:**
  - Strength 1234, Speed 567, coins 8910, upgrade levels 2/3/1 and 4 forests were all back after stopping and restarting Play.
  - Carried seeds came back as 0.
  - The saved Speed set the walk speed right away (51.9).
- **Forced shutdown:** coins 4242 and 9 forests, set less than a second before stopping Play, were saved during shutdown.
- **Two servers:**
  - While the Edit side held the profile, the Play server waited, then took it over after 48 s (ProfileStore's 40 s timeout, since the Edit side never answered).
  - Play then set coins to 5555 and saved on stop.
  - The Edit side then tried to save 999 with its old session. ProfileStore refused: its session ended, and the save still held 5555.
- **New player:** `resetProfile` set everything back to 0; normal loads take under a second.
- StyLua, Selene and luau-lsp pass.

**Not verified:**
- The kick message on the server that loses a session. It's the same `OnSessionEnd` signal the Edit side received.
- An autosave during a session longer than 5 minutes.
- A real outage (the "please rejoin" kick).
- Two live servers.
